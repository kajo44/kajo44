================================================================
Dokumen ini menjadi satu titik acuan agar pengembangan APRJ Next:
- tepat sasaran dan tidak mengulang analisis dari awal;
- memakai alamat file dan tautan repositori yang konsisten;

ATURAN KERJA:
1. Baca dokumen ini sebelum mengubah arsitektur atau fitur.
2. Kerjakan satu checkpoint pada satu waktu.
3. Periksa file yang benar-benar terdampak sebelum mengedit.
4. Jangan mengganti nama file atau memindahkan modul tanpa memperbarui import,
   build script, dokumentasi, dan pemeriksaan.
5. File compatibility lama hanya boleh dihapus setelah import modul aktif, entry point, dokumentasi, dan build script diperiksa. Penghapusan harus dicatat di checkpoint.
6. Setelah perubahan, jalankan pemeriksaan sintaks otomatis dan tes terarah.
7. Jangan menyatakan build atau fitur berhasil jika belum dijalankan dan diuji.
8. Hindari menambah dependency baru kecuali ada manfaat terukur dan kebutuhan nyata.

5. ATURAN EFISIENSI RESOURCE
================================================================
PENGEMBANGAN:
- Ubah file sekecil mungkin untuk menyelesaikan satu masalah.
- Hindari menulis ulang modul besar jika perubahan lokal sudah cukup.
- Gunakan tes sintaks dan tes unit kecil sebelum tes integrasi.
- Jangan mengulang pemindaian seluruh repository jika hanya satu file berubah.
- Jangan menambah framework/dependency hanya demi abstraksi yang belum dibutuhkan.
- Jangan melakukan build portable pada setiap perubahan teks; lakukan setelah
  pemeriksaan sintaks lulus dan perubahan menyentuh build/runtime.
- Jangan memproses seluruh dataset produksi saat menguji bug.

RUNTIME APLIKASI:
- Jalankan operasi berat di worker/background thread, bukan di UI thread.
- Muat foto saat dibutuhkan; hindari menyimpan seluruh foto resolusi penuh di RAM.
- Gunakan cache berbatas ukuran dan bersihkan cache secara aman.
- Hindari memuat model AI berulang kali untuk setiap foto bila model yang sama
  masih dapat digunakan dengan aman.
- Proses dataset secara bertahap/batch; sediakan progress dan pembatalan.
- Hindari duplikasi file gambar tanpa kebutuhan.
- Gunakan query dan indeks SQLite sesuai pola akses yang terukur.
- Hindari mengirim foto ke layanan online secara otomatis; data tetap lokal kecuali
  pengguna secara eksplisit memilih fitur online.
- Untuk training, gunakan batch size yang sesuai RAM/VRAM dan berikan pesan jika
  resource tidak mencukupi.

PRINSIP:
Jangan mengoptimalkan berdasarkan perkiraan saja. Ukur waktu, RAM, penggunaan CPU,
ukuran dataset, dan hasil sebelum serta sesudah perubahan.
